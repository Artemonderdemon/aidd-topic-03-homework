# Функциональные требования: персональный мониторинг акций

## Пользовательские сценарии

1. Вошедший пользователь добавляет акцию в собственный список наблюдения.
2. Пользователь добавляет для акции положительную целевую цену.
3. После очередного успешного обновления котировки приложение сравнивает наблюдаемую цену с предыдущей стороной целевого уровня.
4. Когда цена пересекает уровень вверх или вниз, приложение создаёт внутреннее уведомление.
5. Пользователь просматривает уведомления, отмечает их прочитанными, удаляет ценовой уровень или исключает акцию из мониторинга.

## Проверяемые функциональные требования

1. Список наблюдения принадлежит конкретному пользователю. Пользователь может видеть и изменять только собственные записи.
2. Один пользователь может добавить конкретную акцию в список наблюдения только один раз.
3. Для акции можно задать один или несколько различных целевых уровней. Целевая цена должна быть строго больше нуля; один и тот же уровень для одной записи списка не может дублироваться.
4. При первом успешном наблюдении цены система запоминает, находится ли цена на уровне или выше него, и не создаёт уведомление без подтверждённого перехода через уровень.
5. При последующем переходе цены с одной стороны цели на другую система создаёт одно внутреннее уведомление с целевой ценой, наблюдаемой ценой и временем события.
6. Повторные наблюдения цены на той же стороне не создают повторных уведомлений. После перехода на противоположную сторону система может уведомить о новом пересечении обратно.
7. Уведомления доступны только владельцу списка наблюдения; их можно просматривать с пагинацией и отмечать прочитанными.
8. Удаление акции из списка удаляет относящиеся к ней целевые уровни и уведомления.
9. Мониторинг котировок выполняется существующей фоновой задачей Celery при успешном получении новой цены от Tinkoff. Для доставки уведомлений не используется внешний email или push-сервис.
10. Без входа в систему страницы мониторинга и уведомлений недоступны.

## Изменения архитектуры

- Добавлены модели `WatchlistItem`, `PriceAlert`, `AlertNotification` с внешними ключами к пользователю, акции и ценовому уровню, ограничениями уникальности и положительной целевой цены.
- Проверка пересечения вынесена в `dashboard/services/price_alerts.py`; функция вызывается фоновой задачей после успешного сохранения котировки.
- Добавлены аутентифицированные CRUD-страницы мониторинга, формы, список уведомлений и POST-действие отметки прочитанным.
- Добавлена миграция базы данных `dashboard/migrations/0008_pricealert_alertnotification_watchlistitem_and_more.py`.

Внешние вызовы Tinkoff для интеграционных проверок требуют установленный SDK и действующий `TINKOFF_TOKEN`; логика правил отдельно тестируется без сети.
